Trading and back-office screens keep re-implementing the same handful of awkward fields. A price input that steps by a tick rather than by one. An amount field where typing `10m` means ten million. A date field that also accepts `3M` or `SPOT+1W`. Each is small, each is easy to get subtly wrong, and each tends to get rewritten per project.

This library ships those, plus the ordinary components they sit next to, so a form is one dependency rather than two.

## Try it

The fields below are live. Type `10m` into the amount, or press the up arrow on the rate and watch it move by half a pip rather than by one.

## What it does not do

It has no opinion about your market conventions. Holiday calendars, settlement lag, spot dates and tick grids differ per desk and per currency, so they are injected rather than assumed. The components own the interaction and the accessibility; you own the conventions.

It is also not a data grid, a charting library, or a form-state manager. Each page lists what it does not support, and [Getting Started](?path=/docs/getting-started--docs) has the supported React and browser versions.

## How it is put together

<Unstyled>
  <CardGrid>
    <Card title="Two layers" href="?path=/docs/foundations-styling-and-overrides--docs">
      Every component has an unstyled base carrying behaviour, keyboard handling and ARIA but no
      CSS. The default export adds the styling. Take the base if your design system disagrees with
      ours.
    </Card>
    <Card title="No provider" href="?path=/docs/foundations-theming--docs">
      Theme and density are plain CSS, set with `data-theme` and `data-density` on any ancestor.
      Nothing to wrap your tree in, and nothing that breaks under SSR.
    </Card>
    <Card title="Stable selectors" href="?path=/docs/foundations-styling-and-overrides--docs">
      Each component renders `data-finra-ui="{name}"`. That attribute is public API you can style
      against. The hashed class names are not.
    </Card>
    <Card title="No size prop" href="?path=/docs/foundations-density--docs">
      Sizing comes from the density system, so a whole region resizes together instead of every call
      site passing a size.
    </Card>
    <Card title="Typed" href="?path=/docs/contributing-story-conventions--docs">
      Every exported type, prop and function carries documentation, so your editor explains the API
      without a round trip to these docs.
    </Card>
    <Card title="Accessible by default" href="?path=/docs/foundations-accessibility--docs">
      Components follow the ARIA Authoring Practices patterns, and every story is checked against
      axe in CI.
    </Card>
  </CardGrid>
</Unstyled>
